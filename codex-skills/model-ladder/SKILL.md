# model-ladder

Run the user's task through the Codex runner. Do not implement the task yourself.

1. Locate this SKILL.md on disk using the skill path supplied by Codex. Resolve ../../scripts/codex-run.mjs relative to its containing directory. Do not use CLAUDE_PLUGIN_ROOT or a guessed installation path.
2. Ensure the panel is running before the task: unless `band: false` in `.codex/model-ladder.json` or `MODEL_LADDER_BAND=0`, start `scripts/watch.mjs --cwd <target-repo-root>` from the same package in a persistent PTY terminal and show that terminal using `open_in_codex` when available. Reuse this chat's existing watcher for the repository. Do not wait for the watcher to exit. On a surface without terminal panels, use runner progress output and explain the limitation.
3. Run that script with Node 20+ from the target Git repository root. Pass a JSON object with task and, only if already provided by the user, acceptance as an array of strings. On Windows PowerShell, write the JSON to a uniquely named UTF-8 file in the target repository's .model-ladder directory, then pass --input <absolute-file-path>. Use apply_patch or a literal here-string with .NET WriteAllText and UTF8Encoding to create the file; do not pipe non-ASCII text or Get-Content to Node because Windows PowerShell can replace it with question marks. On other shells, literal UTF-8 stdin is also supported. Never interpolate task text into shell code. The script also accepts a task as one argument.
4. Follow the JSON result. DIRTY means show files and ask whether to run on top of those uncommitted changes, then rerun with allowDirty true only after user authorization. NEEDS_INPUT means ask its message and rerun with the clarified task or the user's acceptance criteria. Never invent approval of criteria. STALE_RUN means inspect .model-ladder/run.json and the live process first. Do not clear a live run's marker. STOPPED means fix the stated environment or ask the necessary clarification before rerunning. ERROR and FAILED mean report the failure. CONFLICT means report the retained patch and worktree paths for review. VERIFIED means report the summary, verified checks, attempt cells and applied files. A report-only task returns its report in summary.

If STOPPED includes errorCode TIMEOUT and resumeRun, rerun the same JSON with that resumeRun. Preserve the original task, acceptance and existing dirty-change consent. Resume at most twice automatically; after that, report the retained worktree and checkpoint. The runner validates the original checkout and configuration, seeds a new worktree from the unverified draft, and verifies the completed result before applying it. If those inputs changed, report the mismatch instead of starting over silently. Do not automatically resume CANCELLED runs or retry unresolved authentication, model-access or sandbox errors. Only VERIFIED exits with code 0; DIRTY, NEEDS_INPUT and STALE_RUN exit with code 2, so always inspect the JSON on nonzero exit. If STOPPED has errorCode USAGE_LIMIT (`usageGuard`, on by default), do not resume automatically: report handoffPath, worktreePath and checkpointPath to the user and resume only after the quota resets.

The same plugin package also supports Claude Code through /model-ladder:run. Codex uses this skill and its own .codex/model-ladder.json settings. Defaults mirror the Claude defaults: gpt-6-luna for Haiku, gpt-5.6-terra for Sonnet and gpt-6.1-sol for Opus. If an account does not expose them, configure available model IDs and supported efforts. Unavailable models stop the run. Optional CODEX_BINARY names the native Codex executable. Keep the installed sandbox and approval controls. Never add bypass flags.

Successful changes are applied without committing or pushing. Existing uncommitted changes are snapshotted without altering the user's Git index. Verification requires an existing configured/discovered test command or acceptance criteria explicitly supplied by the user. All runs record result.json and history under .model-ladder; recommend ignoring that directory.
